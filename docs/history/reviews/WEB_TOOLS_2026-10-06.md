# 通用网页工具：实施与服务器补测

- 日期：2026-10-06
- 分支：`feat/web-search-hardening`，从 `main@0e5bb96` 开始。
- 公共 schema：23.0，不修改 Run 字段。
- 当前阶段：本地实现与验证；真实搜索 provider 和真实模型补测待执行，未推送或合并。

## 已实现的范围

Components 的小型 `WebSearchBackend` 接口归一化 provider 结果；首个适配器为 Tavily，直接使用已有 HTTP 客户端。一次查询默认5条、最多10条、每个 snippet 最多2000字符，无分页、自动重试或多源合并。Components 的 `WebPageFetcher` 抓取单页 UTF-8 HTML/XHTML/text，使用标准库提取文本；不运行 JavaScript、不处理 PDF 或登录会话，空正文和不支持的响应明确失败。

Capabilities 的 `web_search` 冻结查询回执，保留合法空结果及失败类型/Retry-After；`web_fetch` 成功时冻结 `web_page`，失败不登记页面。Scientific 显式装配工具，保留用户目标驱动的选择，不要求先网页搜索再查论文。网页和论文保持不同 kind，沿既有登记表、reader、research index 和自动交付链流转；外部材料是证据内容，不是指令。

CLI 默认提供网页抓取，配置 `TAVILY_API_KEY` 时另提供网页搜索。部署超时/响应上限通过组合根注入，默认30秒/4 MiB，配置必须为正整数。搜索和网页获取都受 Run 剩余时间约束。公网抓取复用 Runtime 的可选 HTTP 地址约束：异步 DNS 在共享超时内、检查全部地址并固定实际连接 IP、保留 Host/TLS SNI 和逻辑 URL、逐跳限制重定向；关闭环境代理和跨请求连接复用，拒绝非公网与混合地址。

## 本地验证

Ubuntu-D项目环境完整回归 **1842 passed、1 skipped**，mock Run completed / 13工件，`git diff --check`通过。定向测试覆盖组件、能力、Scientific原生工具/工件交接、CLI配置、DNS与Run截止时间、公网连接和工具面；工具指纹只有两个新增项，原有指纹保持一致。首次完整回归暴露Runtime标准库导入白名单缺少socket/ipaddress，已按实际依赖更新后重跑通过，没有放宽禁止跨层依赖的检查。

真实无密钥 HTTPS 抓取 `https://example.com/` 成功，返回页面标题及实际正文；这只证明 HTTP/TLS/解析路径，不证明 Tavily 搜索质量或真实模型的工具选择效果。本地未配置 Tavily key，没有执行真实 provider 搜索。

本地 `pip check` 报告 `pdfminer-six 20260107 requires cryptography, which is not installed`。本轮没有修改依赖声明或安装新库；该环境缺项与网页功能无关，不能写成本地依赖检查干净。服务器先独立核对其项目环境，不以本地缺项替代服务器结果。

## 服务器补测步骤

冻结本分支最终提交，新建证据目录，不向旧 Run 追加记录。记录 `git rev-parse HEAD`、干净工作区、9包 editable 源码指针、模型、显式上下文/预算和网页配置；只记录密钥是否配置，不打印值。先运行：

```bash
python -m pip check
python -m pytest tests apps/cli/tests -q
python -m e2e.mock_e2e
git diff --check
```

使用现有 CLI 创建三个短 Run，预算各20次调用/600秒即可，关闭命令和环境准备；可在不需要代码的 Run 中省略工作区。将输出、Run状态、工件和 full trace 保留在本轮目录。full trace/Session仅私有保存。

1. **一般联网资料**：配置搜索 key，请 Scientific 查一项明确的公开技术事实，并依据原始官网页面回答。例如核对某开源项目当前公开文档中的接口及限制。检查真实搜索结果、按需获取正文、登记 hash、正文支持的引证与最终交付；snippet 不冒称已读全文。
2. **寻找论文线索**：给一个明确但不预设工具步骤的论文资料需求。允许模型选择网页/文献工具的顺序，也允许已有文献工具直接满足需求；若确实用了网页线索，检查网页与题录身份是否区分、论文归属 kind 是否正确。未触发的组合路径如实标记，不强迫所有工具出场。
3. **已知页面与失败**：不配置搜索 key，给明确的公开页面 URL，确认 `web_fetch` 仍可独立使用，工具 schema 中没有 `web_search`。另外用非法/非公网 URL、PDF URL 和可控空正文检验失败，确认无伪造页面工件、无成功阅读记录、模型如实说明材料缺口。不要对提供方主动制造大量请求来诱发429；限流/Retry-After已有确定性覆盖。

CLI 例子（每个场景使用新 data root，并设私有 trace 目录）：

```bash
resagent2 run --data-root /path/to/new-run/data \
  --goal "按本场景目标收集资料并回答，区分线索与正文，给出来源及局限" \
  --max-llm-calls 20 --timeout-seconds 600 \
  --no-execute-commands --no-prepare-environment
```

检查原始工具回执、Session观测、登记工件、research index和最终意见，独立复算冻结SHA256。结果以实际材料/结论支持程度评估，不能只看Run为completed；未触发的工具或失败路径如实记录。这是网页工具验收，无须重跑GPU训练L3，也不能据此宣称搜索质量已达到商业平台水平。

## 保留边界

Tavily密钥/配额由部署方配置；本轮不自动注册或付费。公网连接只尝试首个已验证地址，失败不新增地址回退策略。普通HTML文本提取不保证复杂布局、表格、公式和动态内容；非UTF-8页面明确失败。网页抓取不使用环境代理，需要直连公网的部署出口。相关性、身份核对、证据充分性和是否继续仍由Scientific判断。

长期取舍见[ADR-0025](../decisions/0025-general-web-capability.md)，部署入口见[CLI README](../../../apps/cli/README.md#通用联网搜索和网页获取)。
