## 已批准范围

沿用 Tool.input_model、ToolRegistry、AgentLoop、Session 和现有领域上下文。不改科研职责、完成门禁，不新增 Agent、向量库、长期记忆或自动修 JSON。三个阶段各自提交；不自动合并 main，不恢复旧 L3。

1. **串行工具批次**：每轮 1–8 个调用；先整批参数/权限预检，逐个执行/持久化回执。控制工具单独一轮，失败取消后续，恢复区分已完成、结果未知和未开始。
2. **预算去重**：删除 TaskBudget.max_steps；schema 升到 8.0，旧记录原样保留、不迁移。去掉 Scheduler 隐藏的 50 次上限，子模块接收 Run 的剩余模型调用额度和时间；step 保留为动作记录序号。失败、HTTP 重试和压缩调用均入原有调用账本。
3. **最小会话压缩**：仅压力达到阈值或实际组装超限时，摘要较早的完整工具交互，保留近期完整交互；旧历史不删，摘要与边界原子保存。当前领域状态仍由原 builder 提供，摘要不是证据或精确代码。无可用压缩能力/摘要失败/单个巨型回合无法容纳时明确失败，不暗改上限。

## 取舍与边界

- 串行批次不是并行执行，也不是可回滚事务。需要观察前一步结果再决定参数的动作应放下一轮。
- 移除任务隐藏额度后，单个子任务可能用完 Run 余额；不以另一处隐藏数字实现公平分配。
- Run 正常暂停恢复的总调用账本继续累计；直接调用子 Agent 时，调用方负责每次授额。Run/Session/外部副作用不具备跨文件事务，不宣称崩溃计量 exactly-once。
- 128K 是有效输入策略上限而非无限会话长度；模型窗口和输出预留仍独立计量。压缩有损且有调用/延迟成本，不能保证永不遗漏。
- 内置压缩共用客户端传输、trace 和用量；不额外开摘要 Agent，不重复实现 HTTP 重试。
