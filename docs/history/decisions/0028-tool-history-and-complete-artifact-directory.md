# ADR-0028：工具历史与完整工件目录各司其职

日期：2026-10-11。状态：accepted。公共 schema：25.0。

## 背景

同一材料此前可能同时出现在工具回执、第四部分正文工作集和交接索引中。问答、搜索及工作控制还会生成工件，导致正式目录增长，并将结果组织与流程恢复耦合。工件 ID 从内容生成，也不适合先保存身份再完成登记。

系统需要让模型保有明确目标和完整材料入口，通过工具按需取得正文，同时减少交接中的再转述。决定依据见[已确认方案](../reviews/TOOL_CONTEXT_REDESIGN_AGREED_2026-10-11.md)和[源码调研](../reviews/ARTIFACT_INDEX_RESEARCH_2026-10-11.md)。

## 决定

- 所有 Agent 使用固定契约、任务需求、原生工具历史、完整工件目录四部分。只有第三部分可压缩；其他部分放不下时明确报错。
- 搜索返回临时线索，不登记工件。模型显式 fetch 后冻结实际取得的材料；读取只产生工具回执。
- 第四部分只展示授权工件和真实工作导航，全部直接展开。工作产物按 WorkRequest → Task → 原始 Attempt 报告和实际产物组织，不创建索引工件或总体工作报告。
- `request_work` 立即返回稳定工作 ID，完成结果更新目录。业务问答使用直接控制事实并累计到第二部分；操作批准挂起原调用，批准后执行或拒绝并形成唯一最终回执，不进入第二或第四部分。
- 工件统一使用 `artifact_<uuid4.hex>`。UUID 表示身份，SHA256 验证字节；材料复用是来源与快照判断，不由 ID 算法承担。
- 登记先保存分配身份，接收先保存关联事实再确认登记。恢复沿原 ID；外部操作结果未知时不自动重放。Run 和 Session 各自原子保存，不承诺跨存储事务或所有副作用恰好执行一次。
- 删除旧控制工件、ResearchIndex/WorkRecord/WorkFeedback、正文工作集和旧全文工具入口。schema 24.0 及更早状态拒绝恢复，不提供迁移或兼容别名。

## 取代范围与代价

本决定取代 ADR-0017/0018 中的索引与问答工件链、ADR-0020 的总体工作报告、ADR-0022/0025 的搜索工件，以及 ADR-0024 的内容派生工件身份；保留其分工、原件保真、按需阅读和来源校验原则。ADR-0026 的原生工具调用和独立尝试作用域继续有效。

完整目录和业务问答会持续增长，设计选择显式容量失败而非隐藏删项。搜索线索可随历史压缩从模型输入中消失，工具说明要求模型 fetch 需持久保存的材料。原始任务报告减少转述损失，但其内容仍需要主 Agent 判断，不能替代测量证据。

当前实现见 [CONTEXT](../../current/CONTEXT.md) 和 [CONTRACTS](../../current/CONTRACTS.md)；验证范围与服务器步骤见[实施测试计划](../reviews/TOOL_CONTEXT_IMPLEMENTATION_TEST_PLAN_2026-10-11.md)。服务器和 L3 结果须另行记录。
