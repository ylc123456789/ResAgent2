# ADR-0029：有序上级输入、纯任务路由与 Run 打断

日期：2026-10-14。状态：用户确认后实施。schema：27.0。相关旧决策仍作为历史保留，本决策取代 Compiler 改写 Task、子业务问题直接问真实用户及缺少运行中输入的当前行为。

## 决定

Scientific 通过 request_work 给明确 Tasks，仍是自然指令加少量控制字段。无状态 Compiler 只用唯一原生 route_tasks 匹配注册 Agent；固定代码校验并复制原文、共同目标/约束、依赖和输入/输出绑定，不另设语义审查。

所有业务 Agent 使用 ask_user 问直接上级，只有根问真实用户。父方的下级消息/答复属于第三部分，子方的上级答复属于第二部分。父方 reply_to_task 可回答准确问题、澄清自己的未开始或暂停子任务、引用真实用户输入/答案由代码原样转交。升级问题保留因果关系；权限批准仍独立且准确绑定动作。当前执行角色只支持 Scientific 委派 Coding/Experiment，不扩大实际嵌套工作能力。

普通输入立即保存，不取消当前模型回复或已采纳工具批次；下一次模型判断前让原 Scientific 处理，再继续原子 Session/Attempt。`reply_to_task.resume_work=false` 可先逐个任务传递澄清而不恢复子执行；最后一次答复使用 `true`（默认值）再继续工作。未答业务问题和待批准操作仍保持等待。业务问答同样续原会话。第二部分只有一份完整有序业务投影，保留来源与原时间；旧用户记录转发不变成新用户指令。下级待答问题有当前第三部分投影，历史压缩不能使其失联；不造第二套问题索引或问答工件。

显式 interrupt 停止整个 Run 当前执行链：取消本地模型等待、失效迟到未采纳回复，停止受管进程组和子进程，未开始动作不派发。只有停止确认后 paused；确认失败进入明确终态失败。已完成事实、回执、冻结工件和现有文件保留；没有自动文件回滚。模型供应商可能继续计算，已发送调用不退款。

活动 WorkRequest 是打断的特殊生命周期处理：旧委派及未完成 Task/Attempt cancelled，旧子 Session 审计保留且不恢复。继续原 Scientific，由它决定重新委派和显式复用旧材料/工作区。父方也可因新需求而主动结束自己的旧委派；废弃不是新的用户运行模式。

普通未返回工具只有一个 interrupted 回执；已 accepted 请求保持原回执，第三部分通知引用其原 ID，不伪造第二个 tool 消息。问答/控制记录不占第四部分，实际任务原报告和产物继续按 WorkRequest→Task 展开，不生成总体报告。

CLI 发布不可变 input/interrupt 小记录，Controller 是 Run 唯一执行写入者，创建、回答、恢复和导入入口使用 owner 锁。发布顺序另用轻量锁；watcher 只设置取消信号，不覆盖 Run/Session。最终调用期间到达的新输入必须处理后才能完成。

## 验证与边界

离线测试覆盖原文传递、纯路由、来源/时间、直接父问答、同会话恢复、真正进程/HTTP 停止、原生配对、终态收件竞态、真实 PTY Esc 和跨进程 owner 排他。无自动 Git 恢复、通用后台作业管理、任意 Agent 消息总线或分布式调度。真实模型的理解与科研质量仍需 full trace 和独立实验验收，离线测试不作替代。
