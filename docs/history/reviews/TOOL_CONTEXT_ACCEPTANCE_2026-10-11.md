本轮所需的冒烟应只证明数据、GPU 和训练入口能运行。若执行这些命令，会先评价临时模型，再训练和评价正式模型，破坏“最终研究方案确定后才评价 test”的边界。临时流程内部冻结临时 checkpoint，不能替代整项研究的最终冻结。**四次均答 `approve=no`，均未执行**；因此没有据此发生提前模型评价或 test 调参。

### R2：温度拟合只检查有限和正值，没有核验收敛

**发生了什么。** 交付 `calibration/temperature.py` 采用 float64 的 log(T)，调用一次 `LBFGS(lr=0.01,max_iter=50,history_size=10,line_search_fn="strong_wolfe")`；记录实际 30 次迭代。调用方只检查 T 有限、为正，没有记录最终梯度、累计目标求值数或停止原因。

| 检查 | 原交付 | 独立复核 / 预声明阈值 |
|---|---:|---:|
| T | 1.3499949093294425 | 最优约 1.359395886482499 |
| calibration NLL | 0.157728864871719 | 最低约 0.15771670991372935 |
| NLL 距最优差 | 0.000012154957989646 | 最大 0.000001：FAIL |
| 对 beta=1/T 的绝对梯度 | 0.004715134772576931 | 最大 0.00001：FAIL |

独立检查只在冻结 calibration logits 上计算，不用 test 拟合或替换 T。解析目标/导数、Torch 自动求导与有限差分一致，排除了精度、数据和参数化差异。两项失败分别为 `independent_fit_objective_gap`、`independent_fit_stationarity`；T 差距本身是解释提示，不另算失败。

**原因与不确定性。** 优化器可以因为迭代、目标求值或进展限制正常返回，不保证收敛。本环境 Torch 2.5.1 的默认 `max_eval=62`，达到求值上限是有依据的可能解释；未保存 `func_evals/stop_reason`，不能断言具体停机出口。可以确定的是调用方没有检查收敛，而不是“优化器正常返回，所以已找到最优”。

**影响与后续方向。** 差距很小，约占原校准后 NLL 的 0.0077%；原改善、概率和公开指标仍成立。问题是研究核验不完整，不能写成“充分收敛”或“全部数值检查通过”。未来由研究实现选择适合算法的收敛判据，报告最终梯度/目标稳定性、停止状态及剩余误差；实验 Agent 核对关键方法要求，Scientific 按误差大小收窄结论。不要为了这次温度缩放给 Runtime 或完成门槛新增算法专用校验器。

**证据。** `analysis/metrics_independent.json`、`analysis/verify_l3_metrics.py`、`analysis/fit_gradient_readonly.json`、`protocol/L3_FIT_REVIEW.md`，以及原 `temperature.json` 和冻结 `calibration_probs.npz`。

### R3：最坏置信度箱的区间错误逐级进入最终意见

**发生了什么。** 校准后最坏 test 箱实际为 `[4/15,5/15)`，约 `[0.2667,0.3333)`；9 个样本、6 个预测正确、平均置信度 `0.3021688611`、偏差 `0.3644978056`。Experiment 摘要、`comparison_results.json`、Scientific 意见与 final_report 却写成 `[3/15,4/15)`，约 `[0.20,0.2667)`，这个区间容不下平均置信度 0.3022。

**原因与排除项。** 这是明确的区间标签错误；样本数、均值、MCE 数值和代码的箱定义均正确。Scientific 实际读取了汇总和原指标等材料，但没有发现叙述内部矛盾。已有证据不支持归因为索引缺漏、原件篡改或固定 Interpreter 扭曲信息。

**影响与后续方向。** 核心指标改善不因此反转，但分析错误传播，支持结论质量扣 1 分。后续让研究摘要尽可能从同一计算结果产生区间与数字，减少手填边界；Scientific 检查关键叙述是否与原统计自洽。改动应沿角色职责和现有工具推进，不增加总工作报告或二次 LLM 解释层来“修饰”子 Agent 原结果。

**证据。** 原 `comparison_results.json`、Experiment 原报告、最终意见/final_report，以及独立复算的 `analysis/metrics_independent.json` 中非空箱统计。

## 5. 其他观察、比较与原因边界

- **读取 test 文件不等于模型 test 评价。** 冻结前结构诊断打开过 `test_batch` 检查格式、数量和标签范围；未用模型推理或据指标选方案。正式日志第 231 行写冻结 hash、第 232 行开始唯一正式 test 评价；独立验收随后另做前向重放。因此只能说“研究正式评价发生一次且在冻结后”，不能说“test 文件只访问一次”。
- **取得全文不等于读完全文。** 唯一 fetch 的 Guo 论文为 14 页/586 行；Scientific 读取前 120 行，Coding 前 40 行，没有显式读到第 225–237 行的温度缩放方法正文。摘要和初始概念支持有边界的选型，阅读深度仍有限。
- **近似类均衡不能证明分布可交换。** calibration 类别数量约 475–532，test 每类 1000；连续块切分不是随机切分。最终报告已披露 i.i.d./OOD 未测，不能用“class-balanced”替代该论证。
- **复用 checkpoint 入口不等于纯前向重放。** 生成的 `run_experiment.py --checkpoint` 仍会重新拟合 T 并评价 test。独立验收使用原 checkpoint/原 T 的专用前向脚本，没有用这个入口冒充重放；后续生成研究代码应清楚说明入口的实际行为。
- **不能据单次差异归因版本。** 上一轮 `287453b` 测试方评分 10/10、40 epoch，本轮独立评分 9/10、200 epoch；checkpoint、训练决策及审查深度不同。模型随机性可能造成选择和错误差异，但没有控制对照证明其作用，更没有证据证明新版上下文导致质量下降。质量比较需要条件对齐和重复运行。

资料读取深度等是观察和限制，不全部升级成新 bug。未来优先检验 R1 的约束执行、R2 的算法核验和 R3 的证据自洽能力；角色 prompt/工具反馈改动先审查现有链路，再做有证据的局部改进。当前[设计原则](../../current/DESIGN_PRINCIPLES.md)所要求的模型自主判断、近乎无损交接和简洁通用仍适用。
